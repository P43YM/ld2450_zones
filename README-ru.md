# ld2450_zones

<img width="825" height="652" alt="Скриншот от 2026-09-21 182104" src="https://github.com/user-attachments/assets/5cb3e847-ff2c-47e6-b0a6-597a2b8be88b" />

**Умные зоны присутствия для mmWave-радара HLK-LD2450, работающие прямо на ESP32.**

Компонент для ESPHome, который превращает LD2450 в набор зон присутствия — вся логика выполняется на самом ESP. Считывает каждый кадр радара (примерно 10 в секунду), отфильтровывает шум, определяет положение каждой цели относительно зон произвольной формы и отправляет данные в Home Assistant только при реальных изменениях. Зоны рисуются в веб-редакторе, который отдаёт сам ESP, с живой визуализацией движущихся целей. Можно рисовать несколько сегментов в одной зоне и перекрывать их другими зонами. Просто и эффективно — никаких дополнительных скриптов и графиков не требуется.

Работает на платах ESP32 с фреймворком ESP-IDF. Пример собран для ESP32-C3 Super Mini.

---

## Что вы получаете

- **Полноскоростная обработка на устройстве.** Ничего не отбрасывается и не троттлится до оценки, при этом Home Assistant не засыпается координатами.
- **Зоны произвольной формы.** Г-образные, с отверстиями, из нескольких кусков: зона — это просто набор ячеек сетки (по умолчанию 30 × 30 ячеек по 20 см), форма не усложняет логику.
- **Полноценный веб-редактор.** Рисование кистью, прямоугольниками, многоугольниками. Или встаньте в угол комнаты и нажмите кнопку, чтобы поставить вершину многоугольника ровно там, где вы стоите.
- **Присутствие без мерцания.** Зона включается, когда цель появляется в ней достаточно часто, и остаётся включённой заданное время после последнего обнаружения. Оба параметра настраиваются на лету.
- **Зона игнорирования** для вентиляторов, штор, растений и всего, что создаёт фантомные цели.
- **Встроенная диагностика.** Счётчики кадров, пропуски между кадрами, задержки цикла, статус по каждой цели и журнал событий с временными метками — видно, почему что-то произошло.
- **Всё запоминается.** Формы, время удержания и настройки фильтров хранятся во флеш-памяти и переживают перезагрузку.
- **Интерфейс на русском и английском**, переключение в шапке.

## Установка

Добавьте компонент в конфигурацию ESPHome:

```yaml
external_components:
  - source:
      type: git
      url: https://github.com/P43YM/ld2450_zones
    components: [ ld2450_zones ]
```

Работаете с локальной копией? Укажите `path` на папку, содержащую `ld2450_zones/`:

```yaml
external_components:
  - source:
      type: local
      path: components
```

### Минимальная конфигурация

```yaml
esphome:
  name: ld2450-zones

esp32:
  board: esp32-c3-devkitm-1
  framework:
    type: esp-idf

external_components:
  - source: github://P43YM/ld2450_zones
    components: [ ld2450_zones ]

logger:
  hardware_uart: USB_SERIAL_JTAG   # освобождает GPIO20/21 для радара

api:

ota:
  - platform: esphome

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

uart:
  id: radar_uart
  tx_pin: GPIO21
  rx_pin: GPIO20
  baud_rate: 256000                # только такая скорость у LD2450
  rx_buffer_size: 512

ld2450_zones:
  uart_id: radar_uart
  presence:
    name: "Присутствие радара"
  zones:
    - label: "Диван"
      presence:
        name: "Зона Диван"
    - label: "Стол"
      presence:
        name: "Зона Стол"
```

В файле [`example.yaml`](example.yaml) более полный пример со счётчиками и датчиками имён.

Прошейте, откройте `http://<ip-устройства>/` и начните рисовать.

## Конфигурация

### `ld2450_zones`

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `uart_id` | обязателен | UART, подключённый к радару (256000 бод, оба пина). |
| `web_port` | `80` | Порт веб-редактора. |
| `multi_target` | `true` | Переключает радар в режим сопровождения нескольких целей через несколько секунд после загрузки. Установите `false`, если хотите управлять этим самостоятельно. |
| `area_width` | `6000` | Ширина поля зон в мм, с центром на радаре (от 1000 до 10000). |
| `area_depth` | `6000` | Глубина поля зон в мм, вперёд от радара (от 1000 до 8000). |
| `cell_size` | `200` | Размер ячейки сетки в мм (от 50 до 1000). Ширина и глубина должны делиться на него без остатка, максимум 1024 ячейки. |
| `enter_frames` | `3` | Зона включается, когда цель обнаружена в ней не менее этого количества раз… |
| `enter_window` | `10` | …за последние столько кадров (10 кадров ≈ 1 секунда). Не может быть меньше `enter_frames`. |
| `hold` | `5s` | Сколько общее присутствие остаётся включённым после последней обнаруженной цели. |
| `presence` | нет | Бинарный датчик: любая учитываемая цель в пределах поля. |
| `target_count` | нет | Датчик: сколько целей обнаружено сейчас (0–3). Обновляется не чаще раза в секунду. |
| `zones` | `[]` | До 8 слотов зон (см. ниже). |

`enter_frames`, `enter_window` и `hold` — это начальные значения. После нажатия «Применить фильтр» в веб-интерфейсе значения, сохранённые на устройстве, имеют приоритет над YAML.

### `zones[]`

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `label` | обязателен | Начальное имя зоны. Переименовывается позже в интерфейсе. |
| `hold` | `5s` | Сколько зона остаётся занятой после ухода последней цели. Редактируется в интерфейсе. |
| `presence` | нет | Бинарный датчик занятости зоны. |
| `count` | нет | Датчик: сколько целей внутри зоны прямо сейчас. |
| `label_sensor` | нет | Текстовый датчик с текущим именем зоны (см. [Имена зон в Home Assistant](#имена-зон-в-home-assistant)). |

Форма зоны не задаётся в YAML — она рисуется в редакторе. Количество слотов зон фиксируется при сборке прошивки, поскольку сущности Home Assistant статичны.

## Веб-редактор

Откройте `http://<ip-устройства>/`.

- **Поле.** Радар расположен внизу по центру, пунктирный клин — его поле обзора (примерно 60° в каждую сторону). Линии метров идут поверх сетки ячеек, цели отображаются с короткими шлейфами.
- **Инструменты.** Кисть (1×1, 3×3 или 5×5), Прямоугольник и Многоугольник, каждый в режиме «Добавить» или «Стереть».
- **Привязка к цели.** В режиме Многоугольника или Прямоугольника кнопка «Вершина по цели» (клавиша `V`) ставит точку ровно там, где стоит цель. Подойдите к углу, нажмите, перейдите к следующему. Самый быстрый способ обрисовать диван или стол.
- **Горячие клавиши.** `V` — добавить вершину по цели, `Enter` — залить многоугольник, `Backspace` — удалить последнюю вершину, `Esc` — начать заново. Клик рядом с первой вершиной тоже замыкает контур.
- **Сохранение.** Изменения остаются в браузере, пока не нажата «Сохранить зону» или «Сохранить всё». Точка отмечает зоны с несохранёнными правками.
- **Зона игнорирования.** Последний пункт в списке зон. Всё, что стоит в закрашенных ячейках, полностью исключается — и для зон, и для общего присутствия.
- **Фильтрация.** Задайте «обнаружено N раз за последние M кадров» и общее время удержания. Бейдж `3/10` рядом с зоной показывает, сколько кадров в текущем окне содержали цель.
- **Диагностика.** Версия прошивки, количество принятых кадров, битые кадры, пропущенные байты, максимальный разрыв между кадрами, максимальная задержка цикла, обнаруженные и учтённые цели, журнал событий с временными метками.

**Попробуйте без оборудования.** Откройте `ui/ui.html?demo` в любом браузере — симулированный радар.

## Как работает присутствие

Для каждого кадра каждая из (до трёх) целей привязывается к ячейке сетки. Цели за пределами поля или внутри зоны игнорирования не учитываются.

- **Включение.** Зона (или общее присутствие) включается, когда цель обнаружена в ней не менее `enter_frames` раз за последние `enter_window` кадров. Единичный шумовой кадр не сработает; мерцающая цель — да.
- **Удержание.** Пока зона включена, каждое обнаружение перезапускает таймер удержания. Неподвижный человек, которого радар теряет на несколько кадров, не выключит свет.
- **Выключение.** Когда в зоне ничего не обнаружено в течение времени удержания, она выключается.
- **Если радар молчит.** При отсутствии кадров более 2 секунд в логику подаются пустые кадры, чтобы зоны корректно отключались по таймеру.

Home Assistant обновляется только при реальном изменении бинарного датчика. Датчики `count` и `target_count` также ограничены одним обновлением в секунду.

## Имена зон в Home Assistant

Имена сущностей, таких как датчик `presence` зоны, вшиваются в прошивку из YAML, поэтому переименование зоны в веб-редакторе не переименует эти сущности. Чтобы передать текущее имя в Home Assistant, добавьте `label_sensor`:

```yaml
zones:
  - label: "Диван"
    presence: { name: "Зона Диван" }
    label_sensor: { name: "Зона Диван имя" }
```

Публикует имя при загрузке и после каждого переименования — без перепрошивки. Если хотите переименовать сами сущности, сделайте это в настройках сущности Home Assistant (переживёт обновление прошивки) или измените имена в YAML и обновите устройство.

## HTTP API

Редактор общается с устройством через небольшой JSON API, который можно использовать для автоматизации. Аутентификации нет — держите устройство в доверенной сети.

| Эндпоинт | Описание |
|----------|----------|
| `GET /` | Веб-редактор. |
| `GET /api/state` | Живое состояние: цели, занятость зон, счётчики попаданий, диагностика. Интерфейс опрашивает ~10 раз в секунду. |
| `GET /api/zones` | Геометрия сетки, имена зон, время удержания, битовые маски ячеек (строки из `0` и `1`), маска игнорирования, настройки фильтра. |
| `POST /api/zone` | Сохраняет зону. Тело: `<индекс>,<секунды удержания>\n<имя>\n<ячейки>`. Индекс `255` — маска игнорирования. `<ячейки>` — по одному `0` или `1` на ячейку, построчно, начиная от радара. |
| `POST /api/settings` | Сохраняет фильтр. Тело: `<enter_frames>,<enter_window>,<секунды удержания>`. |

## Что нужно знать о радаре

- Координаты в миллиметрах: `x` — боковое смещение от оси радара, `y` — расстояние прямо. Скорость в см/с.
- LD2450 сопровождает до 3 целей, отправляет около 10 кадров в секунду, видит примерно на 6 м вперёд в пределах ~60° в каждую сторону.
- Люди, сидящие абсолютно неподвижно, могут выпадать из сопровождения радара на несколько кадров. Это особенность датчика, а не баг — именно для этого и нужны скользящее окно фильтра и время удержания. Если зона всё ещё мерцает, увеличьте `hold`.
- Сохранённые зоны привязаны к сетке. Если изменение `area_width`, `area_depth` или `cell_size` меняет количество столбцов или строк, сохранённые зоны будут сброшены и их придётся перерисовать. Если количество ячеек остаётся прежним, формы сохраняются и просто следуют новому размеру ячейки.

## Устранение неполадок

| Что видно | Что попробовать |
|-----------|-----------------|
| `Component not found: ld2450_zones` | Репозиторий должен содержать `components/ld2450_zones/`, имя папки должно совпадать с именем компонента. |
| `Component ld2450_zones cannot be loaded via YAML (no CONFIG_SCHEMA)` | Файл `__init__.py` отсутствует, пуст или неправильно назван (по два подчёркивания с каждой стороны). |
| Редактор не открывается | Проверьте `web_port`, убедитесь, что порт не занят другим сервисом, и что устройство в сети. |
| Присутствие мерцает | Откройте «Диагностику» и прочитайте журнал событий. `OFF` должно появляться примерно через `hold` секунд после последней цели. Если `обнаружено / учтено` различаются — цели за пределами поля или в зоне игнорирования. Если радар теряет неподвижного человека надолго — увеличьте `hold`. |
| Цели пропадают и появляются, большие разрывы между кадрами | Почти всегда питание. Используйте качественный источник 5 В и короткий толстый кабель. |
| Диагностика показывает старую сборку | На плате прошивка старше появления диагностики. Пересоберите и перепрошейте. |

## Разработка

Весь веб-интерфейс — один файл [`ui/ui.html`](ui/ui.html), встроенный в прошивку как C++-строка в `components/ld2450_zones/ui.h`. После правки HTML перегенерируйте заголовок:

```bash
python3 gen_ui_h.py
```

Закоммитьте обновлённый `ui.h`: ESPHome собирает из него и не читает `ui.html`.

Логика присутствия (парсер кадров, фильтр, поиск зон) — чистый C++ без аппаратных зависимостей, легко тестируется на ПК. Одно правило при работе со временем: значения `millis()` беззнаковые и переполняются, поэтому сравнивайте их через `elapsed_ms()`, а не вычитанием.

Pull request'ы и баг-репорты приветствуются. При сообщении о проблеме очень помогает скриншот панели диагностики с журналом событий.
